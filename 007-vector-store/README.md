# 007 — vector-store

Векторное хранилище: коллекции с фиксированной размерностью, загрузка векторов
и текста, IVF-индекс (k-means + inverted file), фильтры по метаданным и
гибридный запрос «вектор или текст». Ответ всегда говорит, какой путь сработал:
точный скан или приближённый поиск по слотам.

Идея из [IDEAS.md](../IDEAS.md) №007: «Векторное хранилище: эмбеддинги,
ANN-поиск, фильтры по метаданным».

## Что внутри

| Сущность | Зачем |
|----------|-------|
| `Collection` | размерность, метрика, число слотов, счётчики, признак `trained` |
| `VectorRec` | сам вектор, метаданные (JSON-строка), текущие слоты, версия |
| `SlotRec` | inverted file: слот → вектор, по строке на пару |
| `CentroidRec` | центроид слота, полученный k-means при `POST /v1/index` |

Запись устроена как «слоты → вектор → счётчики». Слот без вектора — лишний
промах при запросе; вектор без слота — потеря для индекса. Первое безобидно,
второе ловится `/stats` и лечится `/index`.

## API

| Метод | Что делает |
|-------|-----------|
| `POST /v1/collections` | создать коллекцию: `name`, `dim`, `metric` (cosine/dot/l2), `nlist`, `nprobe` |
| `GET /v1/collections` | список коллекций |
| `GET /v1/collections/:name` | одна коллекция |
| `DELETE /v1/collections/:name` | удалить коллекцию, векторы, слоты и центроиды |
| `POST /v1/vectors` | upsert одного вектора: `values` или `text` |
| `POST /v1/vectors/batch` | пакетный upsert (до 500, валидация до первой записи) |
| `GET /v1/collections/:collection/vectors/:id` | вектор и его слоты |
| `DELETE /v1/collections/:collection/vectors/:id` | удалить вектор и его слоты |
| `POST /v1/query` | k-NN: `vector` или `text`, `filter`, `nprobe`, `exact` |
| `POST /v1/index` | обучить центроиды и переписать слоты |
| `GET /v1/collections/:collection/stats` | счётчики рядом с тем, что доказывает скан |
| `GET /v1/health` | живость и число коллекций |

### Пример

```bash
curl -s -X POST localhost:8097/v1/collections -H 'content-type: application/json' \
  -d '{"name":"docs","dim":16,"metric":"cosine","nlist":2,"nprobe":2}'

curl -s -X POST localhost:8097/v1/vectors/batch -H 'content-type: application/json' \
  -d '{"collection":"docs","vectors":[
        {"id":"d1","values":[],"meta":"{\"kind\":\"db\"}",
         "text":"a vector database stores embeddings and answers nearest neighbour queries"},
        {"id":"d2","values":[],"meta":"{\"kind\":\"web\"}",
         "text":"a web server answers http requests with json"}]}'

curl -s -X POST localhost:8097/v1/index -H 'content-type: application/json' \
  -d '{"collection":"docs"}'

curl -s -X POST localhost:8097/v1/query -H 'content-type: application/json' \
  -d '{"collection":"docs","text":"vector nearest neighbour search","k":2,"filter":"kind=db"}'
```

Ответ:

```json
{
  "collection": "docs",
  "metric": "cosine",
  "k": 2,
  "probedSlots": [0, 1],
  "candidates": 2,
  "scanned": 2,
  "exact": false,
  "tookMs": 3,
  "hits": [{"id": "d1", "score": 0.84, "distance": 0.16, "meta": "{\"kind\":\"db\"}", "values": []}]
}
```

`exact` — это не «мы старались»: `true` означает, что был полный скан
коллекции (необученная коллекция, `exact: true`, или пробы дали меньше `k`
после фильтра). `candidates` — сколько векторов пришло из слотов,
`scanned` — сколько реально посчитано.

## Как считается

**Эмбеддинги.** `llm.embed` в Arcod пока нет (issue #18), поэтому текст
превращается в вектор детерминированным hashing-эмбеддером: токены и
символьные триграммы раскладываются в `dim` бакетов со знаком, затем L2.
Одинаковый текст → одинаковый вектор в любой операции. Это лексическая
близость, не семантика; README говорит это прямо, а не выдаёт за модель.

**Индекс.** `POST /v1/index` берёт до 2000 векторов, запускает k-means
(первый по id, дальше — самая далёкая точка; 6 итераций) и переписывает
`SlotRec` для всех векторов до 5000. Пустые кластеры сохраняют старый центроид.

**Запрос.** Если коллекция обучена, считаются расстояния до центроидов,
берутся `nprobe` ближайших слотов, из них — кандидаты, кандидаты
пересчитываются точно. Если после фильтра hits меньше `k` — выполняется
полный скан, и ответ честно ставит `exact: true`.

**Фильтры.** `filter` — строка: `tag=red AND year>=2020`, `kind in (a, b)`.
Неизвестный синтаксис — `400`, а не «фильтр проигнорирован». Метаданные
хранятся как JSON-строка: у kv нет типизированных полей, и это осознанный
компромисс.

## Запуск

```bash
cd 007-vector-store
arcod check
arcod build --impl
arcod run --impl --port 8097
./smoke.sh          # чистая сборка, стек, HTTP-проверки, PASS
arcod run --down --impl
```

`smoke.sh` проверяет: создание/конфликт/невалидную размерность, пакетную
загрузку текста, точный ответ необученной коллекции, обучение, приближённый
поиск с ранжированием, фильтры `=` и `in`, `exact=true`, замену вектора,
удаление, расхождение счётчиков со сканом, дубликаты id в пакете, удаление
коллекции и 404 после него.

## Опыт использования Arc

Что понравилось:

- `rules { unique VectorRec.(collection, vid) }` — составной ключ (issue #13
  закрыт) закрывает двойную запись вектора без транзакций;
- `examples` как тесты: две штуки поймали реальный баг рантайма (issue #17),
  причём до запуска Docker;
- курсорная пагинация `io.find` терпимо относится к 5000+ строкам, и это
  ровно тот примитив, которого хватает для скан-фолбэка;
- песочница `impl` не даёт случайно сходить в сеть за «настоящим» эмбеддером.

Чего не хватило (заведены issue):

- **#18, llm.embed.** У `llm` есть `chat` и `model`, но нет `embed`.
  Хранилище без эмбеддера — это калькулятор косинусов; пришлось писать
  hashing-эмбеддер в теле операции и объяснять в README, что это не модель.
  Нужен эффект `llm.embed(texts) -> list<list<float>>` с `dim` в bind,
  чтобы `check` сверял размерность с коллекцией.
- **#17, test и path-параметры.** На `PUT /v1/collections/:collection/vectors/:id`
  пример получал в `values` имя коллекции: при двух path-параметрах индексы
  аргументов съезжают. Пришлось перенести `collection` в тело
  (`POST /v1/vectors`), хотя REST-route был правильный.
- **#19, insert без id.** `io.insert` требует `id` даже когда у сущности
  натуральный ключ. Ошибка — молчаливый `400 Invalid`; `check` молчит.
  В `Collection` пришлось завести `id`, дублирующий `name`.
- **#10 (открыт), нет CAS.** Счётчики `vectors`/`slots` обновляются
  read-modify-write; параллельные записи дадут дрейф. Поэтому `/stats`
  всегда показывает и счётчик, и результат скана — расхождение видно, но не
  исправляется.

Чего не хватает дальше (не issue, а следующий шаг): векторного типа и
провайдера (`vectors`/pgvector/qdrant) — сейчас весь ANN живёт в JS и
упирается в 5000 векторов на операцию; батч-вставки в kv идут по одной
записи; нет `ORDER BY`/агрегатов, поэтому «топ по метрике» всегда считается
в теле.
